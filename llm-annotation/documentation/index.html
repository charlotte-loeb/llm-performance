LLM Coding and Reliability Input

This section documents how icr_list_harmonized.rds, the main LLM-related input of the analysis, was produced. The steps run from the human gold standard through the prompts, the LLM API calls, the harmonization of party codes and the majority vote to the reliability coefficients. The analyses based on this file are documented in the section Reproduction Materials.

Data and coding units

Three LLMs (Gemini 3.1 Flash Lite, GPT-5 Nano and Qwen3 235B) coded texts using the [BLINDED FOR REVIEW] codebook on 17 coding tasks across four levels:

  • News article: section, form of presentation, tone, opposing positions
  • Actors appearing in the article: role, party affiliation, origin, gender, religious affiliation
  • Justifications for political positions: in-group, out-group, common good, religious beliefs
  • Actors' references to other actors: responsiveness, valence, recognition, outrage

Up to 100 units were sampled per country and coding level: 485 articles, 600 actors, 600 justifications and 557 actor references.

Gold-standard data data/text_analysis.csv (1,700 articles), data/actor_analysis.csv (14,374 actors), data/justification_analysis.csv (5,497 justifications), data/actref_analysis.csv (3,770 actor references)
Sample Units are sampled per coding level, up to 100 per country (Australia, Switzerland, Germany, Lebanon, Turkey, USA). The draw is deterministic: set.seed(123), then slice_sample(prop = 1) on the pre-filtered frame, then the first 100 per country. Articles must also have a section (SECTION != 6, not missing), which leaves 485 articles (eligible per country: AU 121, CH 75, DE 117, LB 237, TR 62, US 63). Prompts

All 17 coding tasks use the same zero-shot prompting framework. One request is sent per coding unit, so every article, actor, justification and reference is classified independently. Each request combines five parts:

  • a role instruction
  • the research context
  • the coding task, naming the entity to code
  • the coding instructions quoted verbatim from the codebook (definitions, category lists, decision rules)
  • the full article text

The entity is inserted into the instruction and the article text is appended separately. The prompt therefore works like a fill-in-the-blank text: the model must find the named entity in the running text before assigning categories. A simplified example: 

You are a social science researcher coding news articles for the research
project Mediated Contestation in Comparative Perspective. Your task is to
classify actor {{actor}} mentioned in the article based on these strict
instructions from the MedCon codebook (v7.7).

Actor definition. An actor is an acting subject able to participate
actively in a discourse and identifiable as such.

1. ACT_ROLE_GENERAL. 1 Political: members of government, parliament,
parties. … 14 Representatives of churches, religious or faith communities:
clergymen/-women (Pope, imams, priests). … 19 Others. −99 Not specified.

8. ACT_GENDER. 1 Female, 2 Male, 3 Other, −99 Not specified.

Article text: {{article}}

In this example, {{actor}} = "Pope Francis" and {{article}} = the full article. One prompt file exists per coding level:

  1. *_2026-04-02.txt: the original prompts, exactly as sent in the reported run (the snapshots are byte-identical to the files used at the time). The actor prompt of this generation asks for all 9 actor variables in one request. Only 5 are analysed. The other four (ACT_ROLE_POL_COUNTRY, ACT_ROLE_POL_LEVEL, ACT_ROLE_POL_DOMESTIC_NATIONAL, ACT_ROLE_POL_FOREIGN_NATIONAL) are coded but not analysed.
  2. Current *.txt: condensed versions for the SI Appendix. They keep the same 9 actor sections in shorter wording. The religion list is trimmed (it drops the protestant sub-codes, Druze/Isma'ili, Hindu, Buddhist and "Other"), and the conditional references in ACT_PARTY_AFFILIATION are removed.

Structured output. Responses are constrained by a structured-output schema: a JSON schema that mirrors the codebook categories, so the models return category codes rather than free text. The schemas are defined in schemas.R with ellmer type specifications:

  • type_object with type_enum for categorical variables
  • type_integer for TONE
  • type_boolean for the justification and reference indicators
  • type_string for open codes

ellmer passes the schema to the provider API and returns the parsed fields directly.

From LLM responses to codes

Step Description
Parsing parallel_chat_structured() returns parsed tibbles constrained by the schema. Malformed or failed outputs yield NA; the raw CSVs keep an .error column.
Recoding smart_parse() maps TRUE → 1 and FALSE → 0, parses numeric strings with readr::parse_number(), and otherwise upper-cases and trims the value. It is applied to the LLM codes only. Human codes are kept as stored, and everything is coerced to character.
Party affiliation Free-text party names are mapped onto the country-specific codebook codes (see Harmonization of party affiliation). Names that are not in the codebook are set to missing.
Other open codes ACT_ORIGIN is compared as an upper-cased, trimmed string without harmonization.
Conditional variables Not filtered. ACT_PARTY_AFFILIATION is compared for all actors as coded. Units where either side is missing, including unmatched party names, are dropped by na.omit.

Harmonization of party affiliation

For codebook fields that allow open entries, the models often returned free text instead of the requested values. Human coders coded party affiliation with country-specific numeric codes (e.g. 1 = CDU/CSU in Germany, 6 = FDP in Germany, 12 = FDP.Die Liberalen in Switzerland). The party names returned by the LLMs were therefore mapped onto these codes. The country of the coded article resolves ambiguous abbreviations such as FDP. The mapping is defined in harmonize_party() (preparation/party_harmonization.R) and applies these rules in order:

  1. Values starting with -99 are kept as −99 ("not specified"). Values containing "no party" become 45 ("no party affiliation").
  2. A numeric code is kept if it exists in the codebook and belongs to the article's country, or is not country-specific.
  3. Otherwise the name is normalized (transliterated to ASCII, lower-cased, punctuation and articles such as "party", "die", "the" removed). It is then matched against a list of aliases: party names, abbreviations and translations, including Arabic spellings for Lebanese parties. Aliases for the article's country are tried first.
  4. A name that still does not match but contains "party", "partei" or "partisi" is coded as the country's "Other" category (GER 7, SUI 19, USA 22, AUS 27, LEB 39, TUR 44).
  5. All remaining values stay missing, so they count as neither agreement nor disagreement.

Only ACT_PARTY_AFFILIATION is affected. Compared with the un-harmonized codes, the majority-vote alpha rises from .278 to .643 and the percentage agreement from 69.2% to 85.2%. The per-model alphas rise as follows: Gemini .236 → .608, GPT .178 → .465, Qwen .290 → .441. All other variables are unchanged.

Majority vote

Rule Modal code across the three models, computed per variable and unit
Ties Resolved by first occurrence in model order (which.max(tabulate(...))), i.e. alphabetically: Gemini → GPT → Qwen
Missing model output Missing codes are ignored and the majority is formed from the remaining models. As a result, the majority-vote unit counts match Gemini's and GPT's coverage even where Qwen failed.

Reliability computation

Reliability was computed with tidycomm::test_icr() (tidycomm 0.4.2) with the following parameters:

Unit / coder variables unit_id / coder
Comparisons Four per coding task: each model against the human gold standard, and the majority vote of the three models against it
Coefficients Percentage agreement (Agreement), Krippendorff's alpha (Krippendorffs_Alpha)
Level of measurement TONE is the only ordinal variable (levels = c(TONE = "ordinal")); all other variables are nominal on every level.
Missing values na.omit = TRUE: a unit enters a task only if both coders have a non-missing code. Articles that failed to code therefore count as missing, not as errors.
−99 handling −99 ("not specified") is a valid nominal category, not a missing value. Only actual NA codes are dropped.

Note: Sampling is per level, up to 100 units per country. Only 485 articles pass the article-level filter (SECTION != 6); the actor and justification levels have 600 units each. Qwen's lower counts come from failed structured outputs, which are dropped unit-wise by na.omit, not from a different sample. For ACT_PARTY_AFFILIATION, units are also dropped when the human code is missing or the LLM's party name could not be matched to a codebook code.

Structure of icr_list_harmonized.rds

A named list of five data frames, one row per variable (23 variables on 6 levels). The analysis uses only res_consensus and res_indiv; the levels JUST_REF and POS_REF are not analysed. icr_list_harmonized.rds replaces the earlier icr_list1.rds, which contained un-harmonized party codes. Apart from ACT_PARTY_AFFILIATION, the two files are identical.

Replication of the reliability step

A self-contained replication package re-computes the two elements used in the analysis (res_indiv, res_consensus). It takes the harmonized zero-shot codings and the human gold standard as input. Its output is identical to icr_list_harmonized.rds on all 92 cells (agreement, alpha and number of units). Run it with Rscript compute_reliability.R (about 15 seconds; requires the tidyverse and tidycomm). All files are read and written inside the folder.

File Content
compute_reliability.R Majority vote and reliability computation (agreement and Krippendorff's alpha per coding task and comparison)
data/<level>_human.tsv Human gold standard: unit identifiers and coded categories
data/<level>_zero_shot.tsv Harmonized LLM codings (3 models × sampled units), same columns plus model and COUNTRY. Value formats are normalized to codebook codes, and party names are mapped onto the party codes.
preparation/make_input_files.R Optional: regenerates the input files from the raw LLM responses and the human gold standard (applies smart_parse() and the party harmonization)
preparation/party_harmonization.R Party codebook, alias list, harmonize_party() and smart_parse()
reliability.tsv One row per coding task and comparison (92 rows): level, variable, scale, comparison, model, percentage agreement, Krippendorff's alpha, number of units, number of coders
reliability.rds list(res_indiv, res_consensus) in the column layout of icr_list_harmonized.rds; the analysis scripts can read it in place of that file

Levels: article, actor, justification, actref, posref, justref. All values are stored as text, and codes follow the codebook (−99 = not specified).
