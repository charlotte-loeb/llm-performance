LLM Coding and Reliability Input

The following section documents how icr_list1.rds, the main LLM-related input of the analysis, was produced: from the human gold standard via the prompts, the LLM API calls and the majority vote to the reliability coefficients. The analyses based on this file are documented in the section Reproduction Materials.

Prompts

All prompts are zero-shot. Each one gives the research context, quotes the relevant codebook instructions and ends with the full article text. One prompt is sent per coding unit. The prompt files cover the 17 variables analysed in the manuscript on four levels.

Prompt file Level in icr_list1.rds Coding unit Variables coded
article.txt ARTICLE Article SECTION, FORM_OF_PRESENTATION, TONE, OPPOSING_POSITIONS
actor.txt ACTOR Actor within article ACT_ROLE_GENERAL, ACT_PARTY_AFFILIATION, ACT_ORIGIN, ACT_GENDER, ACT_RELIGIOUS_AFFILIATION
justification.txt JUSTIF Justification of a position JUST_IN_GROUP_REFERENCE, JUST_OUT_GROUP_REF, JUST_COMMON_GOOD_REF, JUST_RELIGIOUS_BELIEFS_REF
actref.txt ACT_REF Reference of one actor to another ACTREF_GENUINE_CONSTRUCTED_RESP_ACTOR, ACTREF_VALENCE_ACTOR, ACTREF_RECOGNITION_ACTOR, ACTREF_OUTRAGE_ACTOR

Prompt versions. Two generations exist:

  1. *_2026-04-02.txt: the originals, as sent in the reported run. The actor prompt of this generation asks for all 9 actor variables in one request, of which only 5 are analysed; the other four (ACT_ROLE_POL_COUNTRY, ACT_ROLE_POL_LEVEL, ACT_ROLE_POL_DOMESTIC_NATIONAL, ACT_ROLE_POL_FOREIGN_NATIONAL) are coded but not analysed. The snapshots are byte-identical to the files used at the time.
  2. Current *.txt: condensed versions for the SI Appendix. Same 9 actor sections but shortened wording; the religion list is trimmed (drops protestant sub-codes, Druze/Isma'ili, Hindu, Buddhist, "Other") and the conditional references in ACT_PARTY_AFFILIATION were removed.

Source of the placeholder values. All placeholder values come from the human gold standard; the LLMs never identify units themselves (unit identification is not evaluated). Placeholders are filled in prompt_generators.R:

Prompt Placeholders Source columns
article.txt {{article}} Article text file joined on Text_ID
actor.txt {{actor}}, {{article}} AKTEURSNAME, article text (actor_analysis.csv)
justification.txt {{article}}, {{position_name}}, {{justification_name}}, {{actor_name}} Article text; POS_POSITION_NAME, JUST_JUSTIF_NAME (justification_analysis.csv); AKTEURSNAME joined via JUST_REP_ACTOR_ID → ACT_IDX
actref.txt {{article}}, {{referring_actor}}, {{referred_actor}}, {{reference_text}} Article text; actor names joined via ACTREF_REFORIG_ACTOR / ACTREF_REFOBJ_ACTOR_ID; verbatim passage ACTREF_REF_ACTOR_TEXT

Structured output. JSON schemas per prompt are defined in schemas.R using ellmer type specifications (type_object with type_enum for categorical variables, type_integer for TONE, type_boolean for the justification and reference indicators, type_string for open codes). Field names, types and allowed values are fixed there.

R package ellmer 0.4.2 (R 4.6.1)

Costs Not logged per request; Gemini and Qwen were free academic endpoints, GPT usage via the OpenAI API

From LLM responses to codes

Step Description
Parsing parallel_chat_structured() returns parsed tibbles constrained by the schema; malformed or failed outputs yield NA (with an .error column retained in the raw CSVs)
Recoding smart_parse() in compare_codings.R: TRUE → 1, FALSE → 0; numeric strings parsed with readr::parse_number(); otherwise upper-cased and trimmed. Applied to LLM codes only; human codes kept as stored (everything coerced to character)
Open codes ACT_PARTY_AFFILIATION and ACT_ORIGIN are compared as upper-cased, trimmed strings without harmonisation
Conditional variables Not filtered: ACT_PARTY_AFFILIATION is compared for all actors as coded; units where either side is missing are dropped by na.omit
Matching to the gold standard unit_id = concatenation of Text_ID and the unit index (ACT_IDX, JUST_IDX, ACTREF_IDX, POSREF_IDX, JUSTREF_IDX), created with unite() per level

Majority vote

Rule Modal code (get_mode()) across the three models, computed per variable and unit
Ties Resolved by first occurrence in model order (which.max(tabulate(...))): Gemini → GPT → Qwen
Missing model output The majority is formed from the remaining models; consensus unit counts match the Gemini/GPT coverage even where Qwen failed

Reliability computation

Reliability was computed with tidycomm::test_icr() (tidycomm 0.4.2). Parameters stored in icr_list1.rds:

Unit / coder variables unit_id / coder
Coefficients Percentage agreement (Agreement), Krippendorff's alpha (Krippendorffs_Alpha)
Level of measurement TONE ordinal (levels = c(TONE = "ordinal")); all other variables nominal, on every level
Missing values na.omit = TRUE: units with a missing code from either coder are dropped
−99 handling −99 ("not specified") is treated as a valid nominal category, not as missing. Only actual NA codes are dropped

Units entering the reliability computation per comparison (n_Units in icr_list1.rds):

Structure of icr_list1.rds

A named list of five data frames, one row per variable (23 variables on 6 levels). The analysis uses only res_consensus and res_indiv; the levels JUST_REF and POS_REF are not analysed.

Element Comparison Rows Columns Used in the analysis
res_indiv Each model vs. human gold standard (Human-gemini_31_flash_lite, Human-gpt_5_nano, Human-qwen3) 69 (23 × 3) Level, Variable, Comparison, Agreement, Krippendorffs_Alpha, n_Units, n_Coders Yes
res_consensus Majority vote vs. human gold standard (Human-LLM-Consensus) 23 As above Yes
res_ensemble Human gold standard and all three models as four coders (Human-LLM-Ensemble) 23 As above No
res_llm Agreement among the three models (LLM-LLM) 23 As above No
res_trad Precision, recall and F1 of the LLM majority-vote codes against the human gold standard (yardstick, macro-averaged, first level as reference) 23 Level, Variable, precision, recall, f_meas No
